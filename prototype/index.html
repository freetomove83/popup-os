팝업스토어 운영을 한 곳에서 —
구인 · 계약 · 출퇴근 · 정산

Gemini PRD(v1.0.0)를 기반으로, 누락된 정산/급여 엔진과 법적 리스크를 보완한 MVP 화면 프로토타입입니다. 스택은 기존 프로젝트와 동일한 Laravel + Vite/React + TypeScript + Tailwind(shadcn/ui) 전제입니다.

MVP = 프로젝트→포지션→지원→계약→출퇴근→정산 정산 Phase 1 포함 관리자 콘솔 + 스태프 PWA 더블엠 내부 운영 우선(dogfooding)

🔴 정산/급여 엔진 누락

User Flow 5의 "정산서 발행"을 받칠 테이블·화면이 전무했습니다. 근무 로그 기반 일급·가산·세금·지급상태를 MVP에 포함.

반영: 정산·급여 화면, 스태프 정산 내역

🔴 Positions 테이블 부재

Applications.position_id가 가리킬 모집 포지션 엔티티가 없었습니다. 프로젝트 하위 포지션(역할·인원·시급·시간)을 1급 시민으로 설계.

반영: 프로젝트·포지션 화면

🔴 check_out 누락

AttendanceLogs에 출근만 있고 퇴근이 없어 임금 계산이 불가했습니다. 출근/퇴근·휴게·정정요청을 모두 기록.

반영: 출퇴근 현황, 스태프 체크인

🔴 파견법 리스크 미검토

대행사가 스태프를 지휘하면 근로자파견으로 해석될 소지. "매칭 플랫폼" 구조·문구를 설계에 반영하고 인사명령 기능은 배제.

반영: 흐름 탭 법적 고지

🟠 전자서명 무결성

캔버스 서명만으로는 취약. 본인확인(PASS)·서명 해시·타임스탬프·계약 필수 기재사항을 계약 화면에 명시.

반영: 스태프 계약 화면

🟠 신뢰도 지표 신뢰 문제

노쇼 0%만 강조하면 표본이 적은 신규가 오히려 유리. 표본 수 노출·객관(로그)/주관(평점) 분리·신규 검증 배지 추가.

반영: 지원자 스크리닝 카드

🟠 실내 GPS 한계

실내 드리프트·위치조작(mock location) 대비. QR(매니저) 1차 + GPS 보조 + 사진 인증으로 설계.

반영: 스태프 체크인, 출퇴근 현황

🟢 로드맵 축소·dogfooding

Phase 1에 6개 제품을 몰아넣은 문서안을 하나의 운영 파이프라인으로 축소하고, 더블엠 내부 운영에 먼저 적용해 스태프 풀을 확보한 뒤 마켓 개방.

반영: MVP 흐름 탭
